* Build an Agentic workflow that generates full project documentation from just a GitHub repo URL. 
* Tech stack: 
  * CrewAI for multi-agent orchestration 
  * Ollama to locally serve DeepSeek-R1 LLM 
* Workflow: 
  * User specifies GitHub repo 
  * Planning crew creates documentation plan 
  * Documentation crew writes documentation according to plan 
  * Generated docs get saved to local directory

* #2) Define Pydantic schema - for robust structured outputs. This ensures data validation and integrity before generating the documentation files.

* #3) Planning Crew (crew.py) - This crew oversees strategy for the outline via: 
  * Code explorer agent -> Analyzes codebase for key components, patterns and relationships. 
  * Doc planner agent -> Creates outline based on codebase analysis as pydantic output. 
* #4) Documentation Crew (crew.py) - This crew writes and reviews the documentation via: 
  * Doc writer agent -> Generates a high-level draft based on the planned 
  * Doc reviewer agent -> Reviews the draft for consistency, accuracy and completeness. 
* #5) Create Documentation Flow (documentation_flow.py) - After setting up our crews, we create the main workflow that: 
  * Clones the GitHub repo 
  * Plans and saves the outline 
  * Generates documentation based on the outline 
  * Saves final docs to local directory 
* #6) Kickoff the flow - Finally, when we have everything ready, we kick off our documentation flow with the GitHub repo URL.

* MCP server that generates documentation from a GitHub repository using CrewAI agents.
	* It clones the code, plans documentation, then uses writer and reviewer agents to produce Markdown/MDX files with Mermaid diagrams.
	* MCP tools let you generate, list, and read the documentation from a connected client.

	* screenshot is correct: Explorer shows 0 KB for the normal file content. It does not include NTFS alternate data streams in that size.
	* checked these files directly and found:

		| File	| Normal content	| Alternate stream content
		|-|-|-|
		| getting_started_guide	| 0 bytes	| 7,012 bytes
		| agent_and_crew_implementation	| 0 bytes	| 8,022 bytes

	* You can verify in PowerShell: ``` Get-Item -LiteralPath 'C:\mak\learn\VibeStudio\docs\getting_started_guide' -Stream * ```

		<img width="600" height="200" alt="image" src="https://github.com/user-attachments/assets/03846527-bcca-4aa3-9e00-fb4c298e89a1" />
	* The old filename contained a colon:
		* On NTFS, : separates a filename from an alternate stream. Windows therefore stored the documentation inside that stream, rather than in the normal file content.
  		* It isn’t a hidden file, so enabling “Show hidden files” won’t reveal it.
		* The filename fix prevents this on future runs after restarting the server. The existing stream content can be recovered into regular .mdx files without regenerating it.

```mermaid
sequenceDiagram
    actor Client as MCP client
    participant Server as server.py / FastMCP
    participant Main as main.py
    participant Flow as documentation_flow.py
    participant Factory as crew.py
    participant Utils as utils.py
    participant Crew as CrewAI
    participant Ollama
    participant Disk as Git / filesystem

    Client->>Server: write_documentation(repo_url)
    Server->>Server: Validate URL
    Server->>Main: run_doc_flow(repo_url)
    Main->>Flow: CreateDocumentationFlow().kickoff()
    Flow->>Disk: Clone repository into workdir
    Flow->>Factory: initialize_planning_crew()
    Factory->>Utils: Load YAML configs and configure LLMs
    Factory-->>Flow: Planning crew
    Flow->>Crew: Analyze repository and generate DocPlan
    Crew->>Ollama: Planning requests
    Ollama-->>Crew: Responses
    Crew-->>Flow: Structured documentation plan

    par save_plan listener
        Flow->>Disk: Recreate docs directory
        Flow->>Disk: Write docs/plan.json
    and create_docs listener
        loop Each planned document
            Flow->>Factory: initialize_documentation_crew()
            Factory->>Utils: Load configs and configure LLMs
            Factory-->>Flow: Writer and reviewer crew
            Flow->>Crew: Draft and review documentation
            Crew->>Ollama: Generation requests
            Ollama-->>Crew: Responses
            Crew->>Utils: check_mermaid_syntax()
            Utils-->>Crew: Modified task output
            Crew-->>Flow: Documentation text
            Flow->>Disk: Write normalized_title.mdx
        end
    end

    Flow-->>Main: Flow result
    Main-->>Server: Result
    Server-->>Client: Success or caught-error message
```
